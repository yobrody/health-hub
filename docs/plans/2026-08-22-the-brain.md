# Health Hub — "The Brain" (contextual insight engine)

_Date: 2026-08-22. The app's central nervous system: turn each user's REAL data into personalized, honest, connected guidance — woven into every screen._

## What it is
One shared **brain engine** that reads the user's real state (profile + goals, today's food log, pantry, weigh-ins + trend, workouts + progression) and produces **personalized insights**. Each screen surfaces the slice relevant to it, as **connected cards with a visible "why."** The interconnection the user asked to *see* is the "why" line — every card traces back to the real data it came from.

## Decisions (locked 2026-08-22)
- **Woven into every screen** (not a central tab): Home shows the top few across kinds; Food/kitchen shows **Buy**; Nutrition shows **Eat**; Gym shows **Train**; Cart shows **Buy/restock**.
- **Connected cards with a visible "why"**: each card shows its action + a `↳ why:` line citing real values; tap to trace to the source screen/data.
- **100% grounded per user — the honesty spine.** An insight only appears when it's genuinely backed by that user's real data. Missing inputs → an honest "set this up" card (e.g. "set a calorie goal to see this"), NEVER generic filler or a fabricated number.

## Insight kinds (v1 — all buildable from existing real data)
- **EAT** — remaining calories/protein vs today's goal (from `nutrition_goals` + today's log); suggest eating, preferring what's in the pantry ("you have chicken + yogurt"). No goal → honest prompt.
- **BUY** — low / expiring / reorder-due items (reuse `restockSoon`) with real context ("used 4 eggs in today's meals"); action = add to the grocery list/cart.
- **TRAIN** — next workout due (from workout history/cadence) + the honest progression suggestion (reuse `evaluateProgression`/`predictNextWeight`); action = start the workout. No history → honest prompt.
- Each insight carries structured **`why` facts** (the real source values) for the traceable card, and an optional **action** (add-to-cart / start-workout / log-meal) that jumps to the right place — making the flow between screens explicit.

## Architecture
- `lib/brain/insight.dart` — `Insight { id; InsightKind kind; String title; String detail; List<WhyFact> why; InsightAction? action; }` (+ `WhyFact{label, value}`, `InsightAction`). Nullable-honest; no fabricated values.
- `lib/brain/brain.dart` — **pure** `List<Insight> computeInsights(BrainInputs)` (inputs = the real state gathered from repos). Deterministic, fully unit-tested, honest (only real-backed insights; missing data → a `setup` insight). Ordered by relevance.
- `lib/brain/brain_providers.dart` — a provider that gathers `BrainInputs` from the existing repos (profile/goals/nutrition/pantry/weigh-ins/workouts) + exposes `insightsForScreen(context)`.
- `lib/design_system/components/insight_card.dart` — the shared connected card (title, detail, expandable `↳ why`, action button); design-system styled, calm.
- **Per-screen wiring**: each screen renders its relevant insights via the shared card; actions route to the target screen (Buy→Cart/list, Train→Gym, Eat→Nutrition) — the visible flow.

## Honesty (non-negotiable)
Every insight + every `why` value comes from the user's real data. No goal/history/pantry → an honest setup prompt, never filler or a guessed number. Personalized by construction (pure function of that user's inputs). No insight implies data we don't have.

## Fits the redesign
Extends the R-5 living loop from mechanical (eat→deplete→restock→cart) to *intelligent* (the brain says what to Train/Eat/Buy and shows why) — woven, clean, per-user.
